## 第二步：問題診斷

1. **大量成果只有「做了什麼」 → 無法證明產生多少價值 → 補上時間、規模、品質或影響範圍**
  例如「完成核心模組」「通過全面驗收」「部署至 production」都沒有使用者數、缺陷數、交付速度或營運範圍。這會讓你看起來像合格執行者，難以和其他三年前端拉開差距。
2. **精選經驗和工作經歷重複 → 浪費首頁最重要的閱讀空間 → 將精選經驗改成含結果的三項代表成就，否則刪除**
  「B2B 平台第二版交付」和「五步驟流程重構」幾乎逐字重複。HR 的閱讀時間很短，相同內容不應出現兩次。
3. **「負責、參與、協助」頻繁出現 → 弱化個人責任邊界 → 改成主導、交付、重構、釐清、建立、協調**
  「參與 CRM／ERP」「協助釐清」「負責 Home Feed」都沒有回答你本人作了什麼決策、承擔什麼結果。
4. **藍新科技有五點且每點過長 → 核心成果被流程細節淹沒 → 壓縮為四點，每點只保留任務、方法和結果**
  目前若不細讀，很難迅速看出最強賣點。第一點應呈現交付速度，第二點呈現重構能力，第三點呈現複雜金融流程，第四點呈現協作與臨時領導責任。
5. **第一段雲端達人經歷過於空泛 → 近兩年工作像沒有具體產出 → 補上系統、模組、技術決策和交付成果**
  「前後端開發與整合」「支援後續維護」適用於大量普通履歷，無法證明你的能力。
6. **技術清單沒有熟練度證據 → 容易被視為關鍵字堆砌 → 按「主要技術／實務經驗」分組並由經歷佐證**
  React、Angular、.NET 和 Monorepo 的實際深度差異很大，不應與 Vue、Nuxt 並排列成同一熟練層級。
7. **日期與格式不一致 → 降低 ATS 解析與整體完成度 → 統一為** `2025.08–至今`
  目前混用斜線、英文月份和 `Present`。`Front-end Developer` 也應與目標職稱 `Frontend Developer` 統一。
8. **2024.05–2024.11 空窗沒有資訊 → 面試官會直接追問 → 若有工作、進修或求職活動，補成可核實的一行**
  不需要掩飾空窗，但需要準備清楚、簡短且一致的說法。
